# 社区参与和贡献指南

## 欢迎来到 Spec-Kit & BMAD-Method 社区！

我们非常高兴你对参与我们的项目感兴趣。无论是报告错误、提出新功能建议、贡献代码，还是改进文档，你的每一份贡献都对我们至关重要。

本指南旨在为你提供清晰的参与路径，确保你的贡献过程顺畅、高效，并得到社区的认可。

## 行为准则

为了营造一个开放、友好、协作的社区环境，我们希望所有参与者都能遵守我们的[行为准则](../CODE_OF_CONDUCT.md)。请在参与贡献前仔细阅读，共同维护一个健康的社区氛围。

## 开发设置

在开始贡献代码之前，请确保你已完成以下基本设置：

1.  **安装 Node.js**: 我们建议使用 v18 或更高版本。
2.  **安装 pnpm**: `npm install -g pnpm`
3.  **克隆仓库**: `git clone https://github.com/Spec-Kit/SpecBmad.git`
4.  **安装依赖**: `pnpm install`

现在你可以开始进行代码修改了！


## 如何贡献

我们欢迎各种形式的贡献，包括但不限于：

- **报告错误 (Bug Reports)**: 发现并报告代码中的问题。
- **功能建议 (Feature Requests)**: 提出新的功能或改进建议。
- **代码贡献 (Code Contributions)**: 修复错误、实现新功能或进行代码优化。
- **文档改进 (Documentation Improvements)**: 完善、修正或撰写新的文档。
- **社区支持 (Community Support)**: 在论坛、聊天室或Issue中帮助其他用户。

### 报告错误

如果你在使用中发现任何错误，请通过以下步骤报告：

1.  **搜索现有Issue**: 在[GitHub Issues](https://github.com/Spec-Kit/SpecBmad/issues)中搜索，确保该错误尚未被报告。
2.  **创建新Issue**: 如果没有找到相关Issue，请创建一个新Issue。在报告中请提供：
    - **清晰的标题**: 简明扼要地描述问题。
    - **详细的描述**: 提供问题的详细信息，包括你期望的结果和实际发生的情况。
    - **复现步骤**: 一步步说明如何复现该错误。
    - **环境信息**: 提供你的操作系统、Node.js版本、工具版本等相关信息。
    - **相关日志或截图**: 如果有，请附上相关的错误日志或界面截图。

### 功能建议

我们欢迎任何关于新功能或改进的建议。请通过以下步骤提交你的建议：

1.  **搜索现有Issue**: 在[GitHub Issues](https://github.com/Spec-Kit/SpecBmad/issues)中搜索，确保你的建议尚未被提出。
2.  **创建新Issue**: 创建一个新Issue，并使用“功能建议”标签。在建议中请详细说明：
    - **要解决的问题**: 描述你希望通过新功能解决的具体问题。
    - **建议的解决方案**: 清晰地描述你建议的功能如何工作。
    - **相关示例**: 如果可能，提供一些使用场景或伪代码示例。

### 代码贡献

如果你希望贡献代码，请遵循以下流程：

1.  **Fork仓库**: 将项目仓库Fork到你自己的GitHub账户。
2.  **Clone你的Fork**: `git clone https://github.com/your-username/SpecBmad.git`
3.  **创建新分支**: `git checkout -b feature/your-feature-name` 或 `fix/your-bug-fix-name`。请使用有意义的分支名。
4.  **进行修改**: 在新分支上进行代码修改。确保你的代码遵循项目的编码规范和风格指南。
5.  **运行测试**: `pnpm test`，确保所有测试都能通过。
6.  **提交你的修改**: `git commit -m "feat: add your feature"`。我们推荐使用[Conventional Commits](https://www.conventionalcommits.org/)规范。
7.  **Push到你的Fork**: `git push origin feature/your-feature-name`
8.  **创建Pull Request (PR)**: 在GitHub上，从你的分支向主仓库的`main`分支创建一个Pull Request。在PR中，请：
    - **关联相关Issue**: 如果你的PR解决了某个Issue，请在描述中添加`Closes #issue-number`。
    - **详细描述你的修改**: 说明你做了哪些修改以及为什么。
    - **确保CI通过**: 等待CI流程完成，并确保所有检查都通过。

### 文档改进

文档是项目的重要组成部分。如果你发现任何错误、遗漏或可以改进的地方，请直接提交PR。对于较大的改动，建议先创建一个Issue进行讨论。

## 编码规范

为保持代码库的一致性和可读性，我们遵循以下规范：

- **代码风格**: 我们使用ESLint和Prettier来统一代码风格。请在提交前确保你的代码通过了检查。
- **命名约定**: 遵循`docs/技术规范与架构设计.md`中定义的命名约定。
- **注释**: 为复杂的逻辑或重要的代码块添加清晰的注释。
