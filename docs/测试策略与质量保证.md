# Spec-Kit & BMAD-Method 整合项目测试策略与质量保证

## 🎯 测试目标与原则

### 测试目标
1. **功能完整性**: 确保所有功能按规范正确实现
2. **系统稳定性**: 验证系统在各种条件下的稳定运行
3. **性能达标**: 确保系统满足性能要求
4. **安全可靠**: 验证安全机制的有效性
5. **用户体验**: 确保良好的用户交互体验
6. **集成兼容**: 验证各组件间的正确集成

### 测试原则
- **测试驱动开发 (TDD)**: 先写测试，后写实现
- **持续集成**: 每次代码提交都触发自动化测试
- **分层测试**: 单元测试、集成测试、端到端测试相结合
- **风险导向**: 优先测试高风险和核心功能
- **可重复性**: 测试结果必须可重复和可验证
- **文档化**: 所有测试用例和结果都要有详细文档

// tests/unit/agents/agent-manager.test.ts
import { AgentManager } from '../../../src/agents/agent-manager';
import { MockAgent } from '../../mocks/mock-agent';
import { MockLogger } from '../../mocks/mock-logger';

describe('AgentManager', () => {
  let agentManager: AgentManager;
  let mockLogger: MockLogger;

  beforeEach(() => {
    mockLogger = new MockLogger();
    agentManager = new AgentManager(mockLogger);
  });

  afterEach(() => {
    jest.clearAllMocks();
  });

  describe('loadAgent', () => {
    it('should load agent successfully', async () => {
      // Arrange
      const agentId = 'test-agent';
      const mockAgent = new MockAgent(agentId);
      
      jest.spyOn(agentManager['registry'], 'getAgentConfig')
        .mockResolvedValue({ id: agentId, name: 'Test Agent' });
      jest.spyOn(agentManager, 'createAgent')
        .mockResolvedValue(mockAgent);

      // Act
      const result = await agentManager.loadAgent(agentId);

      // Assert
      expect(result).toBe(mockAgent);
      expect(agentManager['agents'].has(agentId)).toBe(true);
      expect(mockLogger.info).toHaveBeenCalledWith(
        `Agent ${agentId} loaded successfully`
      );
    });

    it('should return cached agent if already loaded', async () => {
      // Arrange
      const agentId = 'cached-agent';
      const cachedAgent = new MockAgent(agentId);
      agentManager['agents'].set(agentId, cachedAgent);

      // Act
      const result = await agentManager.loadAgent(agentId);

      // Assert
      expect(result).toBe(cachedAgent);
      expect(agentManager['registry'].getAgentConfig).not.toHaveBeenCalled();
    });

    it('should throw error when agent config not found', async () => {
      // Arrange
      const agentId = 'non-existent-agent';
      jest.spyOn(agentManager['registry'], 'getAgentConfig')
        .mockRejectedValue(new Error('Agent not found'));

      // Act & Assert
      await expect(agentManager.loadAgent(agentId))
        .rejects.toThrow('Agent not found');
    });
  });

  describe('executeAgent', () => {
    it('should execute agent with correct context', async () => {
      // Arrange
      const agentId = 'executor-agent';
      const mockAgent = new MockAgent(agentId);
      const context = { projectState: {}, inputData: {} };
      const expectedResult = { success: true, output: 'test output' };

      agentManager['agents'].set(agentId, mockAgent);
      jest.spyOn(mockAgent, 'execute').mockResolvedValue(expectedResult);

      // Act
      const result = await agentManager.executeAgent(agentId, context);

      // Assert
      expect(result).toEqual(expectedResult);
      expect(mockAgent.execute).toHaveBeenCalledWith(context);
    });
  });
});

// tests/integration/workflow-execution.test.ts
import { WorkflowEngine } from '../../src/workflow/workflow-engine';
import { AgentManager } from '../../src/agents/agent-manager';
import { StateManager } from '../../src/state/state-manager';
import { TestContainer } from '../utils/test-container';

describe('Workflow Execution Integration', () => {
  let container: TestContainer;
  let workflowEngine: WorkflowEngine;
  let agentManager: AgentManager;
  let stateManager: StateManager;

  beforeAll(async () => {
    container = new TestContainer();
    await container.initialize();
    
    workflowEngine = container.get(WorkflowEngine);
    agentManager = container.get(AgentManager);
    stateManager = container.get(StateManager);
  });

  afterAll(async () => {
    await container.cleanup();
  });

  beforeEach(async () => {
    await stateManager.reset();
  });

  it('should execute complete workflow successfully', async () => {
    // Arrange
    const workflowDefinition = {
      id: 'test-workflow',
      name: 'Test Workflow',
      steps: [
        {
          id: 'step1',
          name: 'Initialize Project',
          agent: 'project-initializer',
          dependencies: [],
          inputs: [{ name: 'projectName', type: 'string', source: 'user' }],
          outputs: [{ name: 'projectConfig', type: 'object', destination: 'memory' }]
        },
        {
          id: 'step2',
          name: 'Generate Spec',
          agent: 'spec-generator',
          dependencies: ['step1'],
          inputs: [{ name: 'projectConfig', type: 'object', source: 'previous_step' }],
          outputs: [{ name: 'specification', type: 'string', destination: 'file' }]
        }
      ]
    };

    const context = {
      projectName: 'test-project',
      outputDir: '/tmp/test-output'
    };

    // Act
    const result = await workflowEngine.executeWorkflow(workflowDefinition, context);

    // Assert
    expect(result.success).toBe(true);
    expect(result.completedSteps).toHaveLength(2);
    expect(result.artifacts).toContain('specification');
    
    // 验证状态持久化
    const projectState = await stateManager.getProjectState('test-project');
    expect(projectState).toBeDefined();
    expect(projectState.workflow.status).toBe('completed');
  });

  it('should handle step failure and recovery', async () => {
    // 测试步骤失败和恢复机制
    const workflowDefinition = {
      id: 'failure-test-workflow',
      steps: [
        {
          id: 'failing-step',
          agent: 'failing-agent',
          retryPolicy: { maxAttempts: 3, backoffStrategy: 'exponential' }
        }
      ]
    };

    // 模拟代理失败
    jest.spyOn(agentManager, 'executeAgent')
      .mockRejectedValueOnce(new Error('Temporary failure'))
      .mockRejectedValueOnce(new Error('Temporary failure'))
      .mockResolvedValueOnce({ success: true, output: 'recovered' });

    const result = await workflowEngine.executeWorkflow(workflowDefinition, {});

    expect(result.success).toBe(true);
    expect(result.retryCount).toBe(2);
  });
});

### 3. 端到端测试 (E2E Testing)

端到端测试旨在模拟真实用户场景，验证整个系统工作流的正确性和健壮性。

#### 3.1 E2E测试策略

- **测试范围**: 覆盖从CLI交互、工作流执行、LLM调用、状态管理到最终产物生成的完整链路。
- **核心用户旅程**: 
  1. **标准工作流**: `init` -> `specify` -> `plan` -> `tasks` 完整成功路径。
  2. **带自定义配置的工作流**: 用户通过修改`config.json`自定义提示或模型参数。
  3. **失败与恢复**: 模拟Agent执行失败、LLM API不通等场景，验证重试和回退机制。
  4. **交互式与非交互式**: 测试在两种模式下功能的一致性。
- **测试数据**: 
  - 使用固定的、版本化的测试项目模板。
  - 模拟不同规模和复杂度的项目需求。
  - 敏感数据（如API密钥）通过环境变量注入，而非硬编码。

### 性能基准测试（新增）
- 目的：采集工作流执行耗时与内存占用的粗略指标，用于回归对比。
- 脚本：`scripts/benchmark-workflow.js`（默认启用 `BMAD_MOCK_LLM=1` 避免网络噪声）
- 运行：
  - `npm run benchmark:workflow`（默认：`full-development` 工作流，运行3次）
  - 自定义：`BMAD_MOCK_LLM=1 node scripts/benchmark-workflow.js --name planning-only --runs 5`
- 输出：`.bmad/benchmark.json`，包含每次运行的 `elapsedMs`、`rssDelta`、`heapUsedDelta` 以及汇总统计。
- 注意：该脚本直接调用 Orchestrator（非子进程CLI），内存采样为当前进程的相对增量，适合作为趋势观察指标而非严谨的性能报告。
