# SpecKit-BMAD 用户使用手册

本手册面向初学者，帮助你快速使用 SpecKit-BMAD（AI 驱动的软件开发工作流工具）完成从需求到任务拆解、分析、方案、实现、质量保障与报告汇总的完整流程。

---

## 1. 环境要求
- 操作系统：Windows、macOS 或 Linux
- Node.js：`>= 18`
- 包管理器：推荐 `pnpm >= 8`（也可用 `npm`）
- 可选：LLM API Key（如 Anthropic、OpenAI），如果没有可使用离线 Mock。

---

## 2. 安装与启动
1) 克隆项目
```bash
git clone https://github.com/Alphabaijinde/SpecBmad.git
cd SpecBmad
```
2) 安装依赖
```bash
pnpm install
```
3) 构建 CLI
```bash
pnpm build
```
4) 查看帮助
```bash
node dist/index.js --help
```
或使用内置脚本：
```bash
pnpm start -- --help
```

提示：构建成功后，你也可以直接运行 `node dist/index.js <命令>`。

---

## 3. 快速开始（离线模式）
如果没有 LLM API Key，建议使用 Mock（离线）模式：
```bash
export BMAD_MOCK_LLM=1   # Windows PowerShell: $env:BMAD_MOCK_LLM=1
pnpm build
node dist/index.js status
```
运行一个预设工作流（示例：快速规划）并输出到 `.bmad/`：
```bash
node dist/index.js workflow \
  --name planning-only \
  --report-dir .bmad \
  --format markdown \
  --date-prefix
```
执行完整开发工作流（需求→任务→分析→方案→实现→QA→报告）：
```bash
node dist/index.js workflow \
  --name full-development \
  --report-dir .bmad \
  --format json \
  --date-prefix --dedupe
```

---

## 4. 常用命令总览
所有命令都支持 `--help` 查看详细用法。

- `init <project-name>`：初始化新项目
  - 示例：`node dist/index.js init my-app -l typescript -f react -i`
- `status`：查看项目状态概览
- `specify`：生成规格文档（需求→规格）
  - 示例：`node dist/index.js specify -i docs/requirements.md -o .bmad/spec.md --dry-run`
- `tasks`：拆解开发任务
  - 示例：`node dist/index.js tasks -g "购物车功能" -r .bmad -f markdown`
- `analyze`：架构与复杂度分析
- `plan`：制定实施计划
- `solution`：生成解决方案说明
- `implement`：执行代码实现（支持审查）
- `qa`：执行质量保障（单元/集成/E2E/安全/性能）
- `report`：生成汇总报告（Markdown/HTML）
  - 示例：`node dist/index.js report --format markdown --output docs/最新运行报告.md`
- `deploy`：部署到目标环境（支持干跑与回滚）
- `workflow`：运行预设工作流（推荐入门使用）

---

## 5. 预设工作流（推荐）
- `planning-only`：仅规划（需求→任务→简要计划→报告）
- `full-development`：完整开发工作流（需求、任务、分析、方案、实现、QA、报告）

常用参数：
- `-n, --name <name>`：工作流名称
- `-r, --report-dir <dir>`：指定报告目录（自动生成文件名）
- `-o, --output <file>`：输出摘要文件（固定文件名）
- `--date-prefix`：文件名前加日期前缀（如 `YYYYMMDD-HHmmss-`）
- `--dedupe`：避免覆盖；重名追加递增后缀 `-1, -2 ...`
- `-f, --format <fmt>`：`json|markdown`（默认 `json`）

---

## 6. 配置文件与路径
- 项目配置：`./.specbmad/config.json`（如果不存在，命令会自动创建/更新）
- 旧版或快速配置：`./.specbmad.json`（仍支持，内部自动迁移）
- 模板目录：`./templates/`
- 输出目录（默认建议）：`./.bmad/`

你可以在配置中设定：项目元信息、集成工作流模式、输出格式、桥接模式、代理（LLM）配置等。

---

## 7. LLM 设置（在线或离线）
- 离线模式（推荐入门）：
  - 环境变量：`BMAD_MOCK_LLM=1`
  - 默认使用模拟客户端，稳定且不需 API Key。
- 在线模式：
  - Anthropic（Claude）：设置 `ANTHROPIC_API_KEY`（可选 `ANTHROPIC_MODEL`/`ANTHROPIC_BASE_URL`）
  - OpenAI：设置 `OPENAI_API_KEY`（可选 `OPENAI_MODEL`/`OPENAI_BASE_URL`）
- 默认客户端：从配置 `spec_kit.ai_agent` 读取；若不可用自动回退到 `Mock`。

示例（macOS/Linux）：
```bash
export ANTHROPIC_API_KEY=sk_...
export OPENAI_API_KEY=sk_...
```

---

## 8. 输出内容与位置
- 工作流摘要：`./.bmad/workflow.json` 或 `./.bmad/workflow.md`
- LLM 使用仪表盘：`./.bmad/llm-dashboard.md`（或在子目录中按工作流分类生成）
- 状态文件（用于恢复）：`./.bmad/workflow.state.json`
- 报告：`./docs/最新运行报告.md`（通过 `report` 命令或 `npm run report:artifacts` 生成）

---

## 9. 示例从需求到报告
1) 开启离线模式并构建：
```bash
export BMAD_MOCK_LLM=1
pnpm build
```
2) 运行完整工作流：
```bash
node dist/index.js workflow --name full-development --report-dir .bmad --format markdown --date-prefix --dedupe
```
3) 生成汇总报告：
```bash
node dist/index.js report --format markdown --output docs/最新运行报告.md
```
4) 查看结果：
- `./.bmad/` 内的工作流与仪表盘文件
- `./docs/最新运行报告.md`

## 10. 常见问题（FAQ）
- “未知工作流” 错误并退出：检查 `--name` 参数是否为 `planning-only` 或 `full-development`。
- 没有 API Key 怎么办：设置 `BMAD_MOCK_LLM=1` 使用离线 Mock。
- 输出文件覆盖：使用 `--date-prefix` 或 `--dedupe` 防止覆盖。
- 指定输出目录：`--report-dir <dir>` 自动生成文件名并归档到该目录。
- 缓存影响结果：缓存位于 `./.specbmad/cache/llm.json`，可删除以清理；测试模式下自动禁用持久化。
- 日志级别：通过环境变量 `LOG_LEVEL=debug|info|error` 控制（默认 `info`）。

## 11. 测试与质量
- 运行全部测试：`pnpm test`
- 带覆盖率：`pnpm test:coverage`（如覆盖率不达标会失败）
- 生成 KPI/集成报告：
  - `pnpm run report:kpi`
  - `pnpm run report:integration`

---

## 12. 进阶用法
- 自定义工作流：在配置中声明自定义工作流名称与步骤（高级用法，需了解内部结构）。
- 断点恢复：
  - `--resume`：从上次失败处继续
  - `--resume-file <file>`：指定状态文件（默认 `./.bmad/workflow.state.json`）
- 部署：
  - `node dist/index.js deploy --env dev --build --dry-run`
  - 支持策略：`rolling|canary|blue-green`，支持 `--rollback`
