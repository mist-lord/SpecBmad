## 📋 执行摘要

基于对 SpecKit-BMAD 项目当前架构的深入分析（参见 [完整工作原理图](./完整工作原理图.md)）以及与业界同类工具 OpenSpec 的对比，我们识别出三个维度的关键改进机会：**架构级重构**、**功能深度增强**、**用户体验提升**。

本通过旨在指导项目从"可用"向"好用"和"易扩展"进化，重点解决变更管理薄弱、语言支持硬编码、以及迭代开发场景支持不足的问题。

---

## 🏗 1. 架构级改进 (Architecture)

### 1.1 引入 "Delta" 变更模型 (高优先级)
*   **问题**: 当前规范修改是覆盖式的，无法追踪变更历史、原因及影响范围。
*   **方案**: 借鉴 OpenSpec，采用双层规范结构。
    *   `specs/`: 存放当前生效的规范（Single Source of Truth）。
    *   `changes/`: 存放变更提案（Change Proposals）。
*   **实现**:
    *   新增 `Proposal` 数据结构：包含 `reason` (原因), `impact` (影响), `tasks` (任务)。
    *   新增命令 `speckit-bmad change <proposal>`：创建提案骨架。
    *   新增命令 `speckit-bmad merge <proposal>`：将验证后的提案合并入主规范。

### 1.2 语言栈插件化 (Stack Plugin System)
*   **问题**: `src/generator/index.ts` 和 `auto-init.ts` 中存在大量 `if (stack === 'cpp')` 形式的硬编码，难以维护和扩展。
*   **方案**: 定义统一的 `StackPlugin` 接口。
*   **接口定义**:
    ```typescript
    interface StackPlugin {
      name: string;              // e.g., 'cpp-cmake', 'python-poetry'
      detect(cwd: string): boolean;
      generateSkeleton(options: GenerateOptions): Promise<void>;
      getRunCommand(cwd: string): string;
      getTestCommand(cwd: string): string;
      getBuildCommand?(cwd: string): string;
    }
    ```
*   **实施**: 将现有的 TS, Python, C++ 逻辑拆分为独立插件，注册到 `StackManager`。

## 🚀 2. 功能级改进 (Features)

### 2.1 增强 C++ 支持深度
*   **现状**: 仅支持基础 CMake + Main.cpp 骨架。
*   **计划**:
    *   **构建系统**: 增加对 `Makefile` (简单项目) 和 `Ninja` (高性能) 的支持。
    *   **测试框架**: 生成骨架时自动集成 `GoogleTest` 或 `Catch2`，并配置 `CTest`。
    *   **依赖管理**: 提供 `vcpkg.json` 或 `conanfile.txt` 模板支持。

### 2.2 "迭代开发" 工作流支持
*   **问题**: `go` 命令适合从零生成，但在现有项目上进行增量修改（如"添加一个登录接口"）时体验不佳。
*   **方案**:
    *   **增量分析**: 利用 Agent 读取现有代码结构（AST/文件树），而非仅依赖规范。
    *   **精准修改**: 使用 `search_replace` 或 AST 转换工具，而非重写整个文件。
    *   **回归测试**: 修改后自动运行受影响模块的测试。

### 2.3 统一配置管理 (Config Convergence)
*   **问题**: 存在 `.specbmad` 和 `.bmad` (遗留) 两种路径，且部分配置分散。
*   **方案**:
    *   彻底移除所有 `.bmad` 硬编码引用。
    *   实现配置文件的 Schema 验证（使用 Zod 或 JSON Schema）。
    *   支持配置继承（User Config -> Project Config -> CLI Args）。

## 🎨 3. 体验级改进 (User Experience)

### 3.1 交互式首次运行向导 (Wizard)
*   **功能**: `speckit-bmad init --wizard`
*   **交互流**:
    1.  "您想构建什么？" (CLI / API / Web / Lib)
    2.  "偏好语言？" (TS / Py / C++ / Go / Rust)
    3.  "项目名称？"
    4.  "是否需要示例代码？"
*   **价值**: 降低新手认知负荷，避免记忆复杂的命令行参数。

### 3.2 可视化看板 (Web Dashboard)
*   **功能**: `speckit-bmad ui`
*   **内容**:
    *   项目健康度仪表盘（测试覆盖率、构建状态）。
    *   工作流执行进度实时展示。
    *   Agent 对话日志可视化回放。
    *   规范文档的富文本预览与编辑。
