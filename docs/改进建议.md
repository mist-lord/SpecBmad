## 🔴 高优先级改进

### 1. 配置路径统一性问题 ⚠️ 严重

**问题描述**:
- 代码中混用了 `.specbmad` 和 `.bmad` 两个目录
- 配置文件路径不统一：`.specbmad.json` vs `.specbmad/config.json`
- 工作流状态文件使用 `.bmad/workflow.state.json`，但配置使用 `.specbmad`

**具体发现**:
通过代码扫描发现以下路径混用情况：
- **使用 `.bmad` 目录的文件** (15处):
  - `src/workflow/orchestrator.ts`: `.bmad` 目录
  - `src/commands/workflow.ts`: `.bmad/chain.state.json`, `.bmad/workflow.state.json`, `.bmad/artifacts`
  - `src/commands/implement.ts`: `.bmad/artifacts/tasks.md`
  - `src/commands/deploy.ts`: `.bmad/artifacts`, `.bmad/releases`
  - `src/commands/report.ts`: `.bmad/artifacts`
  - `src/plugins/artifacts-indexer.ts`: `.bmad/artifacts`
  - `src/utils/tasks-driven.ts`: `.bmad/artifacts`
  - `src/core/context/manager.ts`: `.bmad/artifacts`

- **使用 `.specbmad` 目录的文件** (8处):
  - `src/utils/config.ts`: `.specbmad.json`, `.specbmad/config.json`
  - `src/commands/specify.ts`: `.specbmad/specifications`
  - `src/core/project/status.ts`: `.specbmad/status.json`

**影响**:
- 用户困惑，不知道文件应该放在哪里
- 可能导致配置读取失败
- 文档与实际行为不一致
- 工作流状态和产物分散在不同目录

**建议方案**:
```typescript
// 统一使用 .specbmad 作为主目录
const CONFIG_DIR = '.specbmad';
const ARTIFACTS_DIR = '.specbmad/artifacts';
const WORKFLOW_STATE_FILE = '.specbmad/workflow.state.json';
const CACHE_DIR = '.specbmad/cache';

// 保持向后兼容：如果存在 .bmad 目录，自动迁移
function migrateOldPaths() {
  const oldBmadDir = path.join(process.cwd(), '.bmad');
  const newSpecbmadDir = path.join(process.cwd(), '.specbmad');
  
  if (fs.existsSync(oldBmadDir) && !fs.existsSync(newSpecbmadDir)) {
    // 迁移逻辑
    fs.renameSync(oldBmadDir, newSpecbmadDir);
    log.info('已迁移 .bmad 目录到 .specbmad');
  }
}
```

**实施步骤**:
1. 创建路径常量文件 `src/utils/paths.ts`
2. 统一所有命令中的路径引用（需要修改至少 23 个文件）
3. 添加迁移脚本（自动迁移 `.bmad` 到 `.specbmad`）
4. 更新文档和示例

**需要修改的文件清单**:

### 4. 错误处理一致性

**问题**:
- 不同命令的错误处理方式不一致
- 有些地方使用 `log.error`，有些地方抛出异常
- 错误信息不够用户友好

**建议**:
```typescript
// 统一错误处理基类
export class CommandError extends Error {
  constructor(
    public code: string,
    message: string,
    public hint?: string,
    public recoverable: boolean = false
  ) {
    super(message);
    this.name = 'CommandError';
  }
}

// 统一错误处理函数
export function handleCommandError(error: unknown, context: string): never {
  if (error instanceof CommandError) {
    log.error(`[${context}] ${error.message}`);
    if (error.hint) {
      log.info(`💡 提示: ${error.hint}`);
    }
    if (error.recoverable) {
      log.info('此错误可以恢复，请检查配置后重试');
    }
    process.exit(1);
  }
  // ... 其他错误类型
}
```

### 5. 配置验证和默认值

**问题**:
- 配置验证不够严格
- 缺少配置迁移机制
- 默认值分散在多个地方

**建议**:
```typescript
// 集中配置验证
export class ConfigValidator {
  static validate(config: ProjectConfig): ValidationResult {
    const errors: string[] = [];
    const warnings: string[] = [];

    // 验证必需字段
    if (!config.projectName) {
      errors.push('项目名称是必需的');
    }

    // 验证代理配置
    if (config.bmad_method?.enabled && !config.agents) {
      warnings.push('BMAD-Method 已启用但未配置代理');
    }

    // 验证路径
    if (config.outputDir && !path.isAbsolute(config.outputDir)) {
      // 转换为绝对路径
      config.outputDir = path.resolve(process.cwd(), config.outputDir);
    }

    return { valid: errors.length === 0, errors, warnings };
  }

  static migrate(config: ProjectConfig): ProjectConfig {
    // 自动迁移旧配置格式
    if ((config as any).bmadMethod) {
      config.bmad_method = (config as any).bmadMethod;
      delete (config as any).bmadMethod;
    }
    return config;
  }
}
```
