# SpecKit-BMAD 使用流程简化方案

**目标**: 让用户能够在最少步骤内开始使用工具，降低学习曲线。

---

## 🎯 当前问题分析

### 使用流程痛点

1. **初始化复杂**
   - 需要手动运行 `init` 命令
   - 需要配置多个选项（语言、框架、代理等）
   - 需要设置 LLM API Key

2. **命令过多**
   - 20+ 个命令，用户不知道从哪个开始
   - 命令参数复杂，需要记忆很多选项
   - 工作流需要多个命令组合

3. **配置繁琐**
   - 需要理解配置文件结构
   - 需要手动配置代理和 LLM
   - 路径和格式选项分散

4. **学习曲线陡峭**
   - 需要理解 Spec-Kit 和 BMAD 概念
   - 需要了解工作流和代理系统
   - 文档分散，难以快速上手

---

## ✨ 简化方案

### 1. 零配置启动（Zero-Config Startup）

**目标**: 用户无需任何配置即可开始使用

**实现**:
- 自动检测项目状态，未初始化时自动初始化
- 默认使用 Mock LLM（无需 API Key）
- 智能默认值（自动检测语言、框架）
- 自动创建必要的目录结构

**代码示例**:
```typescript
// 在命令执行前自动检查和初始化
async function ensureProjectInitialized(): Promise<void> {
  const statusManager = new ProjectStatusManager();
  if (!statusManager.isInitialized()) {
    log.info('检测到未初始化的项目，正在自动初始化...');
    await autoInit();
  }
}

async function autoInit(): Promise<void> {
  // 自动检测项目类型
  const detectedLang = detectLanguage();
  const detectedFramework = detectFramework();
  
  // 使用智能默认值初始化
  const config = new ConfigManager();
  config.save({
    projectName: path.basename(process.cwd()),
    language: detectedLang || 'typescript',
    framework: detectedFramework || 'default',
    spec_kit: { enabled: true, ai_agent: 'mock' },
    bmad_method: { enabled: true, active_modules: ['bmm'] },
    integration: { 
      workflow_mode: 'hybrid', 
      output_format: 'markdown',
      bridge_mode: 'direct' // 默认使用直接模式，无需 Python
    }
  });
  
  // 自动迁移旧路径
  if (ConfigMigrator.needsMigration()) {
    ConfigMigrator.migrate();
  }
}
```

### 2. 一键命令（One-Command Workflow）

**目标**: 一个命令完成从需求到代码的完整流程

**新增命令**: `speckit-bmad go` 或 `speckit-bmad start`

```bash
# 最简单的使用方式
speckit-bmad go "创建一个待办事项应用"

# 自动完成：
# 1. 项目初始化（如需要）
# 2. 需求分析
# 3. 技术规划
# 4. 任务拆解
# 5. 代码生成
# 6. 基础测试
```

**实现**:
```typescript
export async function goCommand(text: string, options: GoOptions): Promise<void> {
  // 1. 自动初始化
  await ensureProjectInitialized();
  
  // 2. 自动检测 LLM 可用性，优先使用真实 LLM，否则使用 Mock
  await autoConfigureLLM();
  
  // 3. 执行完整工作流
  await workflowCommand({
    name: 'full-development',
    format: 'markdown',
    reportDir: PATHS.ARTIFACTS_DIR,
    autoRun: options.autoRun ?? false
  });
}
```

### 6. 自动配置迁移

**目标**: 自动处理配置迁移，用户无感知

**实现**:
```typescript
// 在每次命令执行前自动检查
async function autoMigrateIfNeeded(): Promise<void> {
  if (ConfigMigrator.needsMigration()) {
    log.info('检测到旧版本配置，正在自动迁移...');
    const result = ConfigMigrator.migrate();
    if (result.migrated) {
      log.success(`✅ 已迁移 ${result.files.length} 个文件到新目录结构`);
    }
  }
}
```

```typescript
// src/utils/auto-init.ts
export async function ensureProjectInitialized(): Promise<void> {
  const statusManager = new ProjectStatusManager();
  if (statusManager.isInitialized()) {
    return; // 已初始化，跳过
  }
  
  log.info('🔄 自动初始化项目...');
  
  // 自动检测
  const detected = {
    language: detectLanguage(),
    framework: detectFramework(),
    type: detectProjectType()
  };
  
  // 保存配置
  const config = new ConfigManager();
  config.save({
    projectName: path.basename(process.cwd()),
    ...detected,
    spec_kit: { enabled: true, ai_agent: 'auto' },
    bmad_method: { enabled: true, active_modules: ['bmm'] },
    integration: { 
      workflow_mode: 'hybrid', 
      output_format: 'markdown',
      bridge_mode: 'direct'
    }
  });
  
  log.success('✅ 项目已自动初始化');
}
```

### 3. 自动 LLM 配置

```typescript
// src/utils/auto-llm.ts
export async function autoConfigureLLM(): Promise<void> {
  await llmManager.initialize();
  
  // 检查是否有可用的真实 LLM
  const availableClients = await llmManager.getClientStatus();
  const hasRealLLM = availableClients.some(c => c.available && c.name !== 'Mock');
  
  if (!hasRealLLM) {
    log.info('💡 未检测到 LLM API Key，使用离线 Mock 模式');
    log.info('   提示：设置 OPENAI_API_KEY 或 ANTHROPIC_API_KEY 可使用真实 AI');
  } else {
    log.info(`✅ 使用 LLM: ${availableClients.find(c => c.available)?.name}`);
  }
}
```

## 💡 设计原则

1. **零配置优先**: 默认情况下无需任何配置即可使用

3. **智能默认**: 自动检测和选择最佳配置
4. **错误友好**: 清晰的错误提示和修复建议
5. **向后兼容**: 保持现有功能可用，不破坏现有工作流
