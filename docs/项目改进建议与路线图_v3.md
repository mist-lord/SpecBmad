- [ ] **API Server**: 基于 Express/Fastify 实现本地服务器。

## 🛠 待改进与增强 (Refinement & Optimization)

这些是已识别但在上一阶段未完全实现或可进一步优化的点。

### 1. 智能变更合并 (Smart Merge)
*   **现状**: `ChangeManager.applyDelta` 目前使用简单的字符串追加/替换逻辑。
*   **计划**: 引入 Markdown AST (使用 `remark`)。
    - [ ] **AST Parser**: 解析现有的 Spec 文件。
    - [ ] **Node Locator**: 精准定位到特定的 Requirement 标题节点。
    - [ ] **Structured Merge**: 在 AST 层面进行替换、插入或删除，保证文档结构完整。
*   **价值**: 避免重复追加，保持文档整洁。

### 2. 环境检测增强 (Environment Doctor)
*   **现状**: 插件假设环境工具已安装（如 `cmake`, `python`）。
*   **计划**: 实现 `speckit-bmad doctor` 命令。
    - [ ] 检查当前 Stack 所需的工具链 (Node, Python, CMake, Ninja, GTest)。
    - [ ] 给出具体的安装修复建议（如 `brew install cmake`）。

### 3. 统一配置管理 (Config Convergence)
*   **现状**: 大部分配置已迁移到 `.specbmad`，但 ConfigManager 仍有优化空间。
*   **计划**:
    - [ ] **Schema Validation**: 使用 Zod 对配置文件进行严格校验。
    - [ ] **Global Config**: 支持用户级全局配置 (`~/.specbmad/config`)，用于存储 API Key 等敏感信息，避免每个项目重复配置。

### 4. 自动化测试覆盖
*   **现状**: 已有手动测试脚本，CI 覆盖率待提升。
*   **计划**:
    - [ ] 为 `StackManager` 和 `ChangeManager` 添加单元测试。
    - [ ] 在 CI 中集成端到端测试 (e2e)。
